**Blocked by:** None — parallel-safe with ticket 12 (no shared files).

**Status:** done

**Implementation notes:** `constants.py` gains `RESOURCE_WEIGHTS`, a dict from resource name (or `None` for "no resource") to a spawn weight, appended as a new block after the existing ticket-09 block per the append-only convention. `grid.py` replaces the old `rng.random() < RESOURCE_CHANCE` roll with a single `rng.choices(pool, weights=..., k=1)` call per tile via a small `_roll_resource` helper — still exactly one RNG draw per tile, so existing fixed-seed tests that only assert `revealed`/`claimed` (not resource contents) are unaffected. `WALL_COST` moved to `{"wood": 4}` and `TOWER_COST` to `{"wood": 2, "bricks": 3}` — Tower deliberately spans two resources to exercise `Inventory.spend_all`'s atomic multi-resource path. `gather_task.py`, `build_task.py`, and `task.py` are byte-for-byte unchanged, confirming both were already fully generic over resource/cost keys as the ticket predicted. `tests/test_build.py` needed touching even though it's outside `build_task.py`'s own scope: four of its tests indexed `WALL_COST["crop"]`/`TOWER_COST["crop"]` directly, which no longer exists as a key now that those constants moved off crop — rewrote those four to iterate the cost dicts generically (`for res, amount in WALL_COST.items()`) instead of assuming a specific resource key, which is both correct for the new recipes and more resilient to future recipe changes. `tests/test_grid.py` gained the new coverage: a table-shape test (all 6 non-`None` keys present, weights summing to `1.0`), a weighted-generation test across 10 fixed seeds (union of all resource types across ~27,000 tile rolls equals the full table — deterministic, not flaky, since even the rarest 0.015 weight is astronomically likely to appear), an empty-tile sanity check, and a parametrized test that drives `TASK_TYPES["Gather"].on_complete` directly for each of the 6 resource types to prove `gather_task.py` needed no changes. Full suite: 143 passed (up from a 134 baseline), run 5x to rule out seed-dependent flakiness; `tests/smoke_render.py` prints `smoke OK`.

`/code-review medium` fix: the first weight table split the old flat `0.12` density across all 6 resources (crop/wood down to `0.03` each), which quietly quartered food density while `task.py`'s hunger-eat line still only consumes `crop` (generalizing that is ticket 27's job, out of scope here) — a real starvation-rate regression, and left `wood`/`bricks` so rare (expected ~3.6/~1.8 tiles in the 121-tile starting claim area) that Wall/Tower were barely affordable versus the old design's comfortable margin. Fixed by keeping `crop` at its original `0.12` and adding the 5 new materials as genuinely new density on top (`None: 0.70`, `crop: 0.12`, `wood: 0.07`, `bricks: 0.05`, `marble`/`berries`/`raw_stone: 0.02` each) — food economy unchanged, wood/bricks sized for ~2x cost margin matching the original design's affordability.
